01

기능 요청

채팅이 아니라 작업 요청 한 건을 입력하는 제품형 흐름입니다.

02

AI가 세운 구현 계획

코드를 쓰기 전의 계획과 그 계획이 암묵적으로 기대는 조건을 분리해서 봅니다.

아직 실행 전입니다.
03

코드 작성 전 전제 검증

LLM이 자기 전제를 채점하지 않습니다. 실제 코드·스키마·테스트를 probe가 검사합니다.

검증 대기샘플 기능 검증을 시작하면 핵심 전제가 표시됩니다.
전제 결과가 여기에 표시됩니다.
04

AI의 생각 vs 실제 저장소

거짓 전제를 한 번에 이해할 수 있도록 근거 파일과 실제 관측값을 바로 붙입니다.

저장소 근거가 여기에 표시됩니다.
05

실행 과정

계획 → probe → 차단 → 재계획 → 코드 → 검증.

실행 로그가 여기에 표시됩니다.
06

증거를 반영한 새 계획

거짓 전제를 제거한 뒤에만 소스 수정 권한을 엽니다.

재계획 전입니다.
07

실제 코드 변경

검증된 계획에서 생성된 source-only patch. 테스트와 gate는 수정할 수 없습니다.

코드 변경은 전제 Gate를 통과한 뒤에만 생성됩니다.
08

최종 검증

기존 계약과 새 기능을 같이 검사합니다.

최종 검증 결과가 여기에 표시됩니다.
