01

기능 요청

채팅이 아니라 실제 개발 작업 한 건을 입력하는 흐름입니다.

여기부터는 기술 상세

면접관은 위 결과만 봐도 동작을 이해할 수 있고, 아래에서 근거와 구현 세부를 확인할 수 있습니다.

02

AI가 세운 구현 계획

코드를 쓰기 전의 계획과 그 계획이 암묵적으로 기대는 조건을 분리해서 봅니다.

아직 실행 전입니다.
03

코드 작성 전 전제 검증

LLM이 자기 전제를 채점하지 않습니다. 실제 코드·스키마·테스트를 probe가 검사합니다.

검증 대기30초 데모를 시작하면 핵심 전제가 표시됩니다.
전제 결과가 여기에 표시됩니다.
04

AI의 생각 vs 실제 저장소

거짓 전제를 근거 파일과 실제 관측값에 바로 연결합니다.

저장소 근거가 여기에 표시됩니다.
05

실행 과정

계획 → 전제 추출 → 저장소 검사 → 차단 → 재계획 → 코드 → 검증.

실행 로그가 여기에 표시됩니다.
06

증거를 반영한 새 계획

거짓 전제를 제거한 뒤에만 소스 수정 권한을 엽니다.

재계획 전입니다.
07

실제 코드 변경

검증된 계획에서 생성된 source-only patch. 테스트와 Gate는 수정할 수 없습니다.

코드 변경은 전제 Gate를 통과한 뒤에만 생성됩니다.
08

최종 검증

기존 계약과 새 기능을 함께 검사합니다.

최종 검증 결과가 여기에 표시됩니다.
LLM은 제안하고, 저장소가 판정합니다. 계획·전제·재계획·patch 제안에는 LLM을 쓸 수 있지만, 사실 판정은 실행 가능한 저장소 probe와 테스트가 담당합니다.
