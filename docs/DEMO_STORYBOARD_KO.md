# 30초 한글 데모 스토리보드

## 0–5초 — 문제 이해

첫 화면 문구:

> **AI가 코드를 쓰기 전에, 틀린 전제부터 잡습니다.**
>
> 기능 요청을 받은 AI가 구현 계획을 세우면 PlanProbe가 그 계획이 기대는 전제를 실제 저장소에서 먼저 검증합니다.

버튼: `샘플 기능 검증 시작`

## 5–12초 — 계획과 전제

요청:
`글로벌 이벤트 보상에 연속 접속 보너스를 추가해줘. 기존 재시도와 지역별 시간 규칙은 유지해야 해.`

전제 카드 4개가 나타난다.

- ❌ 모든 이벤트 일정은 UTC다.
- ❌ 요청 하나에는 region 하나만 존재한다.
- ✅ 동일 idempotency_key는 기존 receipt를 재사용한다.
- ✅ receipt 계산 뒤에 ledger write가 수행된다.

가운데 큰 상태:

> **잘못된 핵심 전제 2개 발견 — 코드 생성 차단**
>
> 아직 소스 파일은 0개 수정되었습니다.

## 12–20초 — 저장소 근거

거짓 전제를 클릭하면 실제 근거가 바로 보인다.

- `config.py` — KR=`Asia/Seoul`, JP=`Asia/Tokyo`, US=`America/Los_Angeles`
- `models.py` — `regions: list[str]`

기술 용어보다 `AI의 생각` vs `실제 저장소`를 시각적으로 대비한다.

## 20–26초 — 재계획과 코드

> **실제 근거를 반영해 계획을 수정했습니다.**

- 지역별 기존 시간 판정 유지
- 다중 region 유지
- idempotency guard 유지
- 검증된 위치에 streak bonus 삽입

그 뒤 실제 코드 diff를 표시한다.
